# Journal — cross-cutting, 2026-09

The narrative, verbatim and dated. **Never read at boot**: reached by `grep` when a precise
question is asked. Reversals are **kept** here — that is what this file is for.

## 2026-09-17 — the repository is extracted from a private monorepo

The directing-context system was running inside a private VPS canonical holding five
applications. Extracted here as its **form**: protocol, map, selectors, guards and a worked
example, with none of the original content — app fiches, journal and memory corpus stay
private, and imported third-party knowledge was excluded outright for lack of an established
redistribution licence.

Two changes were made during extraction rather than after, because both were repo-specific
literals that an adopter would have had to edit in code:

- The root node of the context map was `system.vps`, named after one host. Now `system.root`.
- Application aliases were a hard-coded dict in the compiler — the single place that knew the
  fleet. Now **derived** from the map's application nodes plus an optional `aliases` field
  added to the schema. Adopting the tool no longer means editing it, and forgetting to declare
  an app is no longer silent: the alias table is empty for that app, so a task naming it
  partitions nothing.

Measured before the change: five aliases for four applications, all of them unusable by any
other repository.

## 2026-09-17 — five of the upstream guard's rules were not extracted

Upstream carries eighteen rules. Fourteen are here. The four left out bind to surfaces this
repository does not have: two halves of a concept→class map over PHP and JavaScript, the
epistemic-substrate maps, and the design-system registries. Naming the omission rather than
renumbering silently: an adopter who reads "R1 to R14" and finds a gap will look for the
missing one, and the gap is the honest signal.

## 2026-09-17 — the proof campaign found its own false negative

First full run of `prove-guards.sh`: 13 rules proven red, and R1 reported "mutation failed to
apply". The mutation was `yes 'filler' | head -700 >> fiche`. It applied perfectly — the fiche
was over its ceiling on disk — but `head` closes the pipe, `yes` dies of SIGPIPE, and the
mutation's exit status came back non-zero. The harness read that status and reported a failure
to mutate.

Measured: the file was 31.5 KB after the mutation, and R1 does fire on it. The defect was in
the proof harness, not the rule. Replaced with a `seq` loop, which returns zero.

Worth recording because of the direction of the error: the harness reported a **failure**,
which is the loud side. Had the pipeline been arranged the other way — a producer whose
non-zero status was swallowed — the campaign would have reported R1 proven while never testing
it. The lesson is filed in memory as [[a-pipeline-status-can-lie]].
